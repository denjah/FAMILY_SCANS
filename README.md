# Семейный фотоархив

Приватная Next.js-консоль для локального семейного фотоархива. Оригиналы читаются только сервером; браузер получает отдельные WebP-превью после авторизации. Комментарии и вручную введённые сведения о снимках сохраняются в SQLite-базе. В опубликованном каталоге имя карточки — имя файла, а автоматические подписи отключены: текст на hover и в просмотрщике появляется только после ручного ввода.

## Первый запуск

Требуется Node.js 24.11.1 или совместимая 24.x версия.

```powershell
pnpm install
pnpm setup:secrets
pnpm index
pnpm build
pnpm start --hostname 127.0.0.1 --port 3000
```

`setup:secrets` один раз показывает семейный пароль, пароль владельца и локальную ссылку приглашения. Сохраните их в менеджере паролей. `.env.local`, manifest, БД и превью исключены из Git.

## Временная защищенная ссылка

Перед публикацией укажите HTTPS-адрес туннеля в `ARCHIVE_PUBLIC_ORIGIN` внутри `.env.local` и перезапустите production-сервер. Это значение участвует в CSRF-проверке и выдаче `__Host-` cookie.

Предпочтительный вариант после установки `cloudflared`:

```powershell
cloudflared tunnel --url http://127.0.0.1:3000
```

Если загрузка `cloudflared` недоступна, временный TLS-туннель можно поднять встроенным OpenSSH:

```powershell
ssh -o StrictHostKeyChecking=accept-new -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -R 80:127.0.0.1:3000 nokey@localhost.run
```

Замените начало локальной ссылки приглашения на выданный HTTPS-домен, сохранив путь `/i/<invite-token>`. Компьютер, Next.js и tunnel должны оставаться включенными. Анонимный адрес временный и изменится после переподключения; для постоянного адреса нужен named tunnel или приватный full-stack-хостинг с постоянным диском.

## Резервная копия комментариев

Остановите приложение и скопируйте каталог `data` на другой физический диск. При работающем сервере сначала завершите его штатно, чтобы SQLite закрыл WAL. Никогда не копируйте только `archive.sqlite`, оставляя рядом `archive.sqlite-wal`.

## Синхронизация комментариев с Vercel

На странице `/owner/comments` кнопка **«Синхронизировать с общей базой»** объединяет записи локальной SQLite и общей базы Vercel. Одинаковые ID не дублируются; синхронизация переносит и отметки удаления. Для защиты обмена создайте случайный секрет длиной не менее 32 символов и задайте его как `ARCHIVE_COMMENT_SYNC_SECRET` и в локальном `.env.local`, и в переменных проекта Vercel. На локальном компьютере задайте `ARCHIVE_COMMENT_SYNC_URL` как полный адрес API общей версии, например `https://<домен-vercel>/api/admin/comments-sync`. После добавления переменных перезапустите локальный сервер и заново разверните проект Vercel. Не публикуйте секрет и не добавляйте его в Git.

## Обновление архива

После добавления новых оригиналов выполните `pnpm index`. Стабильные идентификаторы существующих путей сохранятся. Индексатор не переименовывает и не изменяет оригиналы.

### Альбомы и ручные сведения

Ветки `МАМА`, `PAPA` и `DEN` показаны группами по папкам. Для `МАМА` порядок такой: корень `ALENA`, `MAMA`, `mama_piter`, `NASTJA`, затем остальные подпапки. Карточка объединяет варианты одного снимка; слайдер над фото переключает варианты, а Bridge-стек использует отдельную обложку.

Откройте фото и заполните поля **Имена на снимке**, **Год снимка** и **Подпись**. Эти данные сохраняются для конкретной карточки и видны пользователям после обновления страницы. Вносите только сведения, которые подтверждены архивной записью или семейным свидетельством; предположения обозначайте в тексте. Не используйте имя файла, прежнюю подпись, папку или стилистику фото как подтверждение даты или личности.

В сетке доступны режимы **Мозаика**, **Средние**, **Мелкие** и **Таблица**. В мозаике превью подгружаются постепенно.

### Кнопка синхронизации веб-архива

Локальный администратор может пересканировать папки, создать WebP-копии (не больше 1600 px) и загрузить их в подключённую папку Google Drive одной кнопкой. Для сервисного аккаунта в `.env.local` на локальном компьютере добавьте:

```dotenv
ARCHIVE_SYNC_ENABLED=1
GOOGLE_DRIVE_FOLDER_ID=<идентификатор-папки-экранного-архива>
GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON='<полный JSON сервисного аккаунта в одну строку>'
```

Откройте эту папку Google Drive в браузере и дайте адресу `client_email` из JSON роль **Редактор**. Те же `GOOGLE_DRIVE_FOLDER_ID` и `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON` нужно добавить в переменные окружения проекта Vercel; там достаточно доступа на чтение. После перезапуска локального альбома кнопка **«Синхронизировать веб-архив»** появится только у администратора.

Синхронизация каждый раз пересчитывает индекс, включая стеки `.BridgeSort` и их главные снимки. Экранные WebP для неизменённых исходников повторно используются; локальный `.export-state.json` хранит контрольные суммы исходников и не отправляется в Drive. Перед загрузкой файлы сравниваются с контрольными суммами Drive, поэтому уже опубликованные неизменённые фото не передаются заново. При первом запуске после обновления кода существующий экспорт сопоставляется по размеру и времени изменения исходников. Исходники в семейных папках не изменяются. Vercel получает новый manifest из Drive автоматически; из-за серверного кэша это может занять до 5 минут. Для запуска без интерфейса: `pnpm index`, затем `pnpm export:screen`, затем `pnpm sync:screen`. Принудительный полный пересчёт локальных WebP доступен через `ARCHIVE_SCREEN_EXPORT_REPLACE=1 pnpm export:screen`. Если изменился только индекс, можно использовать `ARCHIVE_SCREEN_SYNC_MANIFEST_ONLY=1 pnpm sync:screen`.

Вместо сервисного аккаунта можно использовать личный OAuth-доступ: добавьте `GOOGLE_DRIVE_OAUTH_CLIENT_ID` и `GOOGLE_DRIVE_OAUTH_CLIENT_SECRET`, затем выполните `pnpm authorize:drive` и завершите вход Google в открывшемся браузере. Полученный refresh token остаётся в локальном `.env.local`.

Запуск синхронизации изменяет данные на Google Drive, поэтому его выполняют только при намеренной публикации. Индексация и экспорт без синхронизации безопасны для оригиналов и Drive.

Машиночитаемые результаты находятся в закрытом каталоге `data`: `archive-index.json`, `index-errors.json` и `verification-report.json`. Они содержат приватные пути и поэтому исключены из Git.

## Защита

- Нет фотографий в `public/`.
- Страницы, комментарии и медиа требуют подписанной сессии.
- Чувствительные документы скрыты от contributor-роли.
- Пароли хранятся как PBKDF2 hash, session secret и invite token — только в env.
- `ARCHIVE_SESSION_VERSION` можно увеличить, чтобы разом завершить старые сессии.
